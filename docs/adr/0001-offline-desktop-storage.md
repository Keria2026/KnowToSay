# 0001：离线桌面端采用 Tauri 与 SQLite

## 状态

已接受。用户明确指定 Tauri，并在获知 AGENTS 原定 PostgreSQL 的约束后，明确批准桌面端使用 SQLite。决策记录于 2026-10-18。

## 背景

首版需要 Windows 10+ 安装式客户端，可离线运行，不部署独立公网服务端。管理员电脑负责局域网资料发布；业务员维护本地个人话术。预估每组约 2,000 条话术、20–30GB 知识库素材。

AGENTS 的基础规范面向 SvelteKit、Rust、SQLx 与 PostgreSQL。为每台业务员电脑安装和维护 PostgreSQL 服务会增加桌面安装、离线运行和恢复成本。

## 决策

- 使用 Tauri 作为桌面应用框架，保留 Svelte 5、SvelteKit、TypeScript Strict、Bun、Rust Stable 和 SQLx。
- SQLite 保存本地结构化数据，包括话术、流程、个人修改和搜索索引。
- 图片、视频、Excel 原文件保存在应用数据目录，数据库保存元数据与文件引用。
- 管理员客户端内置局域网同步能力，不依赖独立公网服务端。局域网 HTTP 接口继续遵循 Axum、Rust 契约和统一错误规范。
- 此决策只批准桌面端存储例外，不决定未来独立服务端的数据库。

## 替代方案与取舍

| 方案 | 取舍 |
| --- | --- |
| 每台电脑安装 PostgreSQL | 符合模板数据库规范，但需要额外数据库服务，增加安装和日常维护负担。 |
| 所有电脑直接使用管理员数据库 | 无法满足管理员离线时业务员独立使用和保留个人分支的要求。 |
| SQLite 与本地素材文件 | 无需单独数据库服务，适合离线桌面应用；需要显式实现发布、同步和一致性恢复。 |

## 后果

- SQLite 迁移必须版本管理，沿用 SQLx 访问；数据库特有 SQL、时间类型和查询检查需按 SQLite 实现。
- 管理员版本与个人修改必须有明确的数据边界，不能通过覆盖整个数据库文件实现更新。
- 数据库与素材文件需共同校验和备份；不能假设复制正在写入的数据库文件就能产生一致备份。
- Windows 安装、系统剪贴板、LDCLOUD 交互和真实局域网行为需要在目标平台验证；当前决策不代表这些能力已经实现。
